# 模型接入使用说明

适用版本：0.2.3。模型是可选的辅助复核；没有Key也能导入文件、运行规则评测并生成比赛结果。

## 在网页接入

1. 启动工作台，点击顶栏“模型接入（可选）”，展开配置区。
2. 填接口地址、模型名称、API Key和单次超时秒数。接口地址支持基础地址（例如服务商提供的HTTPS地址加 `/v1`）或完整 `/chat/completions` 地址。
3. 点击“保存设置”。保存后密码框清空，不会回显Key；相同地址下留空可沿用本次运行已保存的Key，更换地址须重新填写。
4. 点击“测试连接”。只发送一条不含用户轨迹的测试记录，同时检查认证、JSON返回格式和证据引用；测试本身不会启用复核，也不会改动当前报告。
5. 勾选“下次开票检查启用AI辅助复核”，再点击“保存设置”。启用后所选任务内容、完整操作记录和规则结论会发送到所填服务，只应用于已获授权的数据和服务。
6. 选择开票JSONL并点“开始检查”。顾问示例仍用规则检查。界面显示模型成功/失败数量；案例中的“为什么这样判断”包含“可选的AI复查”，完整报告同样标明复核情况。

当前报告模式说明已生成报告实际用了什么；下次检查模式说明下一次点击将用什么。修改或清除设置不会重新计算旧报告。未保存的表单会阻止开始检查，避免无意使用旧设置。

## Key与失败处理

- 网页配置只保存在本机服务进程内存，不存入浏览器localStorage/sessionStorage、配置文件、报告、日志或提交包。重启程序后需要重新填写；“清除设置”立即忘记Key并关闭模型模式。
- 模型意见写入 `semantic_review`；不覆盖处理正确性、出票结果、根因和规则分数。超时、401、无效JSON或虚构事件编号都会记为模型复核失败，规则结果仍保留，不能把接口失败算成开票机器人的错误。
- 网页不保存模型缓存。CLI可使用输出目录中的本地结果缓存，但不写入Key。服务返回的复核文字若回显本次Key，会在输出和缓存前隐藏。
- 配置只适用于当前启动的工作台。关闭一个端口的设置不会影响另一个独立工作台；配置页不接受跨站来源请求。

## 接口协议

本版支持 Chat Completions 风格的文本JSON响应：发送 `model`、`messages`、`temperature=0` 和 `response_format={"type":"json_object"}`，使用 `Authorization: Bearer <Key>`，读取 `choices[0].message.content`。
仅允许HTTPS；本机模拟服务可用HTTP。禁止自动重定向，避免携带认证信息跳转。单次超时范围1—180秒，逐条复核一条运行；8个A/B任务会有16次模型请求，耗时取决于模型服务。

不承诺所有平台或协议直接兼容。Responses接口、流式接口、其他厂商独有协议或不支持 `response_format` 的服务，需要另做适配；没有因网页配置入口而声称已完成真实赛事模型联调。

## 命令行接入

在本机PowerShell设置环境变量。不要把真实Key写进提交材料或共享脚本：

```powershell
$env:TRACEGUARD_MODEL_BASE_URL = "https://经授权的模型地址/v1"
$env:TRACEGUARD_MODEL_NAME = "服务商或赛事提供的模型名称"
$env:TRACEGUARD_MODEL_API_KEY = "仅在自己的终端填写Key"
$env:TRACEGUARD_MODEL_TIMEOUT = "45"
python -X utf8 -B -m traceguard evaluate --cases "你的开票轨迹.jsonl" --judge advisory --output artifacts/model_review
```

需要官方Schema校验时，另外指定 `--schema "官方资料目录/06_提交格式.schema.json"`。
命令行环境变量不会被网页自动启用；网页必须显式保存并开启，默认不会因为系统设置了Key就发送轨迹。

## 本次验证范围

本机模拟服务验证了保存与清除、连通性测试、启停、模型成功/HTTP失败/格式错误/超时、规则结果不变、Key不落盘以及重启后忘记设置。没有使用真实Key，没有调用真实外部模型或赛事端点。
