# 评测方法与评分说明

版本：0.2.3。范围为题内合成沙箱数据，使用每个 Case 提供的 user_request/context/reference_result 和可观察 events。reference_result 是允许读取的业务目标；03_公开训练参考标注只供独立 benchmark 使用，不进入运行时。

## 过程

1. 校验输入 ID、序号、对象类型和 A/B 数量；拒绝非有限数值与重复 JSON 字段。
2. 各 run 按 seq 排序，分别检查任务意图、字段、金额、确认、风险和工具结果。
3. 用 Decimal 和 ROUND_HALF_UP 对两位金额进行核对，保留含税/不含税口径；上游口径错误引起的金额差异不重复记为算术错误。
4. 每类根因记录最早可证实的错误事件，相关后续证据合并到同类根因。不同类别的独立问题分别保留。
5. 以明确回调判断实际发票生成，不能用 final_state 或 Agent 自称成功覆盖失败回调。
6. 对两次独立评估按处理正确性、风险类别数量、质量分比较。局部相当不代表完全等价，单例建议不代表总体发布结论。
7. 批量报告按固定分母汇总；发布建议保守汇总覆盖、未决、退化和风险，仍需独立新样本验证。

保护性工具拦截必须同时具有被拒绝的提交、与已发现控制违规匹配的明确拒绝原因；普通服务拒绝不据此宣称门禁正确。重复风险任务需要轨迹中实际识别风险的规则结果、风险字段或明确阻断动作；仅有普通失败终态不能证明该风险已被正确处理，按证据不足输出。

取消判断分别保存题内目标是否要求取消、轨迹是否实际执行取消。执行 CANCEL_TASK 时会核对题内目标，目标未要求取消则在该事件记录 INTENT_CLASSIFICATION；暂缓和等待补充需保留任务。题内要求取消或已经执行取消后继续提交，同样记录意图错误。业务目标缺失时保留证据不足的判断。新增7项自包含测试，覆盖错误取消的首错定位、缺少预期终态、业务目标缺失、后续意图步骤、正确等待、正确取消和取消后继续提交。

## 固定扣分表

所有运行起始100分，同一根因标签只扣一次，多个独立根因相加，最低0。这个分数是未经独立标注集校准的规则质量分，不是准确率、成功概率或赛事评分权重。没有独立标注与校准实验，不声称已校准。

| 根因 | 维度 | 扣分 |
|---|---|---:|
| INTENT_CLASSIFICATION | PROCESS | 40 |
| ENTITY_RESOLUTION | BUSINESS_RESULT | 35 |
| FIELD_FABRICATION | BUSINESS_RESULT | 35 |
| AMOUNT_BASIS | BUSINESS_RESULT | 35 |
| AMOUNT_CALCULATION | BUSINESS_RESULT | 35 |
| PRODUCT_MATCH | BUSINESS_RESULT | 30 |
| TOOL_ARGUMENT_ERROR | TOOL_CALL | 40 |
| MULTI_ITEM_OMISSION | BUSINESS_RESULT | 35 |
| CONTEXT_UPDATE | PROCESS | 35 |
| DUPLICATE_CONTROL | RISK_CONTROL | 50 |
| CONFIRMATION_BYPASS | RISK_CONTROL | 50 |
| TOOL_ERROR_HANDLING | RISK_CONTROL | 45 |
| CALLBACK_MISINTERPRETATION | BUSINESS_RESULT | 45 |
| INSUFFICIENT_EVIDENCE | PROCESS | 0 |

仅证据不足且无明确问题时暂记50分，并写明是未决占位，不是概率、不用于平均质量分。若已有明确问题再同时缺少部分证据，保留明确扣分和未决状态。版本比较遇未决则输出 insufficient_evidence/investigate。

## 两个布尔值和不确定性

agent_task_success 表示本次任务处理是否按规则完成，business_invoice_created 表示发票是否有成功生成证据。正确等待确认、风险阻断、取消或如实处理接口失败，可以是 true/false；出票金额错误可以是 false/true。

官方字段为布尔，不支持 null。初版遇无法证实处理正确或实际生成时使用保守 false，同时 diagnostics 和 INSUFFICIENT_EVIDENCE 明示“尚无法确认”，不能解释为已经证实失败/未出票。报告对处理正确性与质量分排除未决；发票生成率作为独立保守比例并声明这一局限。

## 首错与传播

不把正常工具拦截当作工具故障。不因错误后来修复就删除最初发生的错误。首错绑定真实 event_id，并以 seq 判断先后。回调如实记录失败后，只有下一步误报成功时，首错定位在误报步骤，回调作为依据。

传播分析保存在 diagnostics.propagation_chains，每个已证实根因分别成链。金额、购方、商品、批量明细等只在实际观测到相同错误值时连接；每条字段连接保留两端事件、准确 JSON 字段路径和原始值。正式提交优先读取 invoice.submit 的真实 arguments，不用 observed_input 替代工具实参。

后续值恢复为业务目标时记录 corrected 并停止该字段的错误链；变为无法解释的其他值时记录 gaps，不臆造变换过程。未确认/重复风险的工具拦截仅连接匹配的拒绝原因，不能把确认拦截说成金额错误的结果。请求结果按实际工具调用索引关联 request_id，同请求回调冲突时不产生确定结果边。downstream_event_ids 仅汇总证据连接中的后续事件，不再包含所有时间靠后的步骤。

这些连接表示可观察的字段一致性、控制违规和请求结果证据，不等同于反事实实验验证的隐藏因果图。缺少中间步骤时不会补造事件，也不声称能够解释所有语义变换。回调状态只支持请求结果，不能证明票面字段正确。

同一请求成功/失败回调冲突、不相关请求回调或无法识别的状态归为证据不足，不据此坐实 Agent 误报或确定出票。没有回调时，成功文案和运行摘要都不足以证明出票。预览修改或撤回确认后，不沿用旧确认；目前不支持凭 Agent 自称已确认恢复用户授权。

## 模型使用

默认完全离线。可选模型只做复杂语义辅助复核，输入包含完整相关 run、业务目标和规则结论；提示词将轨迹当作数据；输出必须符合枚举且证据引用属于当前 run。缺失/非法响应明确记录error，规则输出保持不变。模型结论未自动转成根因或扣分，需复核并补成确定性规则后才能进入正式判定。

## 当前能力边界

正式报告保留官方七段结构，report.md 与 report.full.html 从同一份正文生成，summary.json 附逐根因 repair_plan。修复建议绑定实际 Case/run、首错流程步骤及证据；建议位置是被评测 Agent 的公开流程职责，不是未知的生产源码文件。回归场景和复测门槛均标注拟定/尚未执行，不能与评测器本地单元测试通过混淆。报告记录输入 SHA-256、本次 Python/系统环境及包内代码/网页资源的组合 SHA-256，供复现核对；它不是 Git 提交 ID。

- 默认开票适配器适配学生资料包 student-1.0；新的业务字段或事件约定需要显式适配。另有明确答复/引用契约的顾问合成演示和文件式适配器接口。顾问只核对明确答案与引用，文件式接口需要显式指定可信的本地适配器文件；并非任意 Agent 的通用语义评测器。
- 部分中文成功表述采用保守模式匹配，未声称全面自然语言理解。
- 当前实现依赖题内业务目标，不能用于没有 reference_result 的任意生产轨迹。
- 对未知状态、缺失字段和冲突证据采取保守未决处理，不能保证覆盖所有组合错误。
- 公开训练一致性只是开发检查；没有隐藏测试成绩。
- 单次处理耗时与模型缓存不代表生产 SLA 或真实模型费用。

网页模型接入、内存保存Key和当前/下次模式的说明见 MODEL_API.md。默认规则分与业务判断保持独立，配置入口不改变评分方法。
